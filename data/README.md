## Контракт v1.0

`schema.py` — исполняемая схема, `example.schema.json` — её JSON Schema.
`examples/synthetic.jsonl` — два вручную созданных синтетических примера без трасс.

- `session_id`, `messages`: ID, роль и исходный текст каждого сообщения.
- `gold_entities`: ID, message_id, entity_type, start/end, точный text.
- `detections`: те же спаны плюс detector, detector_version, confidence и trace.
- `detector_run_id`, `trace_origin`: происхождение результатов (`actual`,
  `unit_test`, `not_run`). Искусственные трассы допустимы только в unit-тестах.
- `gold_verdicts`: TP/FP требуют detection_id, TP/FN — gold_entity_id.
  TN относится ко всей пустой сессии. Смешанные случаи описываются несколькими
  вердиктами, а не единственным классом сессии.
- `source`: dataset, revision, license, source_id, group_id, split, url;
  `metadata` для дополнительных сведений.

Позиции — индексы Unicode code points Python, полуинтервал `[start, end)`
относительно конкретного сообщения. Это не UTF-8 bytes и не UTF-16 JS offsets.
Проверяются границы, точная цитата, ID и ссылки, конечный confidence [0,1],
структура вердикта. Неизвестные поля запрещены; coercion отключён.
`detections: null` = не запускали; `[]` = запуск завершён без срабатываний.
Загрузчик не выводит TP/FP/FN/TN из отсутствующих логов.

`trace` пока расширяемый словарь: он сохраняет исходные сигналы, но не доказывает
правдивость происхождения или полноту причин. Общего формата у backend ещё нет.
Перед интеграцией нужно согласовать с Толей ID/роли/вердикты и Unicode offsets,
с Михаилом — ID запуска, версии, trace, пороги и таксономию. После согласования
добавить адаптер либо вынести контракт в backend/schemas отдельным изменением.
Автоматическое сопоставление сущностей и полнота вердиктов — будущая задача метрик.

## Загрузка и проверка

Из корня репозитория:

```bash
uv sync --locked
uv run python -m data schema data/example.schema.json
uv run python -m data validate data/examples/synthetic.jsonl
uv run python -m data load-redmadrobot --output-dir data/raw/redmadrobot-v1
uv run python -m data validate data/raw/redmadrobot-v1/examples.jsonl
uv run pytest
uv run ruff check .
uv run ruff format --check .
```

В окружениях с read-only home перед командами задать:
`export UV_CACHE_DIR=/workspace/work/uv-cache`.
Для повторного импорта использовать новое имя output-dir: существующий каталог
не перезаписывается. Для offline: добавить `--input /path/to/test.csv`;
локальный источник отмечается `local_unverified` и получает SHA256 — переданная
revision сама по себе не подтверждает происхождение локального файла.

Результаты: source.csv (для HTTP), examples.jsonl, rejections.jsonl, manifest.json.
Revision — фиксированный commit SHA, manifest содержит checksum входа,
версию адаптера, фильтры, число строк/сущностей и политику split.
BIO проверяется строго: orphan I и неизвестные типы отклоняются.
Токены сопоставляются последовательно, без пропуска непробельных символов;
регистр может различаться, исходный текст не меняется. Неустранимые ошибки
попадают в rejection-журнал с индексом строки без текста PII.
Отсутствие строки в результате не является исправлением исходной разметки.

Локальный прогон фиксированной revision: **2841 исходная строка, 2840 приняты,
1 отклонена, 0 дубликатов, 5612 сущностей**. Исходная card заявляет 5614.
Отклонена строка с source_id `1431` (нумерация с нуля): пустой токен.
Она исключена целиком, без автоматической правки двух сущностей.
Это характеристика импорта, не оценка качества детектора.
Манифест без исходных текстов сохранён в `reports/redmadrobot-manifest.json`.

Все импортированные строки остаются в исходном test. Нельзя использовать этот
test для калибровки или подбора порогов. Дедупликация — по точному тексту;
group_id = SHA256 текста. Она не обнаруживает семантические дубликаты и не
восстанавливает неизвестное авторское родство примеров. При генерации диалогов
нужно наследовать group_id родителя и делить по группам до генерации.
