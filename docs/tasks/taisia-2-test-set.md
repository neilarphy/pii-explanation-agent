# Таисия, задача 2: замороженный тестовый набор test-v1

**Зачем.** Агента мы дорабатывали, глядя на свои 65 сценариев, поэтому «253/253» на них — подгонка, а не
качество. Нужен набор, который никто из разработчиков агента не видел: на нем один раз в конце считаем
итоговые цифры (агент, детектор, поиск пропусков) с доверительными интервалами. Набор собираешь ты, и
до финального прогона его не видит никто, кроме тебя.

**Сроки:** отпечаток (см. ниже) — до 23.11, готовый набор — до 26.11.

## Что собрать

**60 диалогов** (можно больше), 2–8 реплик, на русском (5–10 штук с английскими вставками — можно).

Откуда — не из наших наборов и не нашим генератором:
- **не меньше 20 написать руками** — по мотивам реальных переписок (поддержка, HR, банк, доставка);
- остальные — сгенерировать моделью, которой у нас нет в агенте и генераторе (не qwen и не deepseek;
  например, GPT, Gemini, Claude через свой чат) по своим промптам, и **вычитать и разметить руками**.

**Темы** — две группы:
1. **Чат поддержки** (как сейчас), ~30 диалогов.
2. **Запросы к LLM-ассистенту** (трафик, который видит HiveTrace), ~30 диалогов: пользователь вставляет
   письмо, резюме, таблицу, кусок лога или кода и просит переписать, перевести, кратко пересказать,
   найти ошибку; ассистент отвечает и может повторить данные из запроса.

**Что внутри** — примерно так, по всему набору:

| Что | Сколько фрагментов | Категория |
|---|---|---|
| Имена (в т.ч. в падежах, строчными, имя-отчество), телефоны, почта, адреса | 60+ | `pii` |
| Документы: паспорт, ИНН физлица, СНИЛС, права, свидетельство о рождении, военный билет, полис ОМС | 25+ | `pii` |
| Номер карты | 5+ | `pii` |
| CVC, коды из СМС, пароли, токены и ключи API | 10+ | `sensitive` |
| Ловушки: реквизиты организаций, номера заказов и договоров, служебные контакты, тестовые карты, IP сервера, слова без значения («мой телефон») | 30+ | `none` |
| Спорные: номер без контекста, «передайте Соколову» (человек или компания) | 5–8 | `ambiguous` |

Трудные формы — обязательно: значение разбито на две реплики, записано словами («восемь девятьсот…»),
с опечаткой или пробелами («ivan . petrov @ mail . ru»), исправлено пользователем («ой, не 5, а 6 в конце»),
повторено ботом. Хотя бы 8 диалогов совсем без ПДн.

Политика, что считать ПДн, — [docs/pii-policy.md](../pii-policy.md), раздел 3 (кратко — в задаче 1).
Если по политике не ясно — ставь `ambiguous` и пиши в `domain`, что именно спорно.

## Формат

Пример — [data/labeling/test-v1/template.draft.jsonl](../../data/labeling/test-v1/template.draft.jsonl).
Одна строка — один диалог (JSON):

    {"domain": "llm_document", "session": {"id": "ts-llm_document-1", "messages": [
       {"turn": 0, "direction": "in", "text": "..."}, {"turn": 1, "direction": "out", "text": "..."}]},
     "gold": [{"turn": 0, "text": "Иван Сергеевич", "type": "NAME", "cat": "pii"}]}

- `id` начинается с `ts-`, уникальный; `direction`: `in` — пользователь, `out` — бот или ассистент.
- В `gold` — **все** ПДн, секреты и ловушки, каждое вхождение отдельно (повтор ботом — тоже).
- `text` — дословно из реплики; если такой текст в реплике встречается дважды, добавь `"occurrence": 2`.
  Офсеты писать не надо — их посчитает скрипт.
- `type` — один из: NAME, PHONE_NUMBER, EMAIL, ADDRESS, DATE_OF_BIRTH, PASSPORT_NUMBER, INN, SNILS,
  OGRNIP, DRIVER_LICENSE, BIRTH_CERTIFICATE, MILITARY_ID, OMS, BANK_CARD_NUMBER, BANK_ACCOUNT, CVC,
  SMS_CODE, TOKEN, OGRN, KPP, IP_ADDRESS, OTHER.
- `cat` — `pii`, `sensitive`, `none` или `ambiguous`.

Проверка (ошибки покажет с номером строки):

    uv run python -m scripts.testset build --in test-v1.draft.jsonl

## Как заморозить

1. Черновик держи **у себя**, не в репозитории и не в общих чатах.
2. Когда набор готов — посчитай отпечаток и пришли **только его** (строкой в PR или в чат):

        uv run python -m scripts.testset hash --in test-v1.draft.jsonl

   Отпечаток доказывает, что набор не меняли после того, как увидели результаты.
3. Файл отдаешь, когда агент заморожен (Анатолий скажет, ориентир — 28–29.11). Тогда:

        uv run python -m scripts.testset build --in test-v1.draft.jsonl --out data/scenarios/test-v1.jsonl

   и PR. Прогон — один раз, результат идет в отчет как есть, правок агента после этого не делаем.

или ошибка эталона. Эталон после прогона правим только с записью причины в `data/scenarios/gold-fixes-v1.json`.
