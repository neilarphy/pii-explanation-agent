# PII-Bench: HTTP-прогон v4 на GPU

Профиль `pii-ru-en-v4`, политика `2.1.0`, 16 правил. Изменены регулярки адресов и паспортов и их проверка контекста. Модель, NER-метки, пороги `0.20 / 0.50` и политика merge не менялись.

## Методика и границы сравнения

Выполнен **новый полный HTTP-прогон v4 с реальным GPU-forward для каждого текста** на `hivetrace/pii-bench@cd6a18ace16daf23e79247ccf1e2b245d4054654`: 900 текстов `domain` и 910 текстов `entity`, всего 1810. Использованы ранее скачанные данные той же ревизии, исходные тексты и прежняя разметка. Пропусков и HTTP-ошибок: **0**. Метрики подсчитаны `2026-11-21T14:45:23.406760+00:00`.

До этого выполнялся replay сохранённых модельных кандидатов v3 с новыми регулярками. Новый HTTP-прогон **точно воспроизвёл `entities` и `trace.candidates` того replay во всех 1810 текстах**. Модельные кандидаты в новом прогоне и v3 совпали во всех текстах по метке, типу, окну, границам и score с точностью до шести знаков; модельные метаданные также совпали. Контрольный replay самого исходного профиля v3 ранее точно воспроизвёл его ответы по entities и candidates.

## Условия запуска

- GPU: NVIDIA GeForce RTX 3060 Laptop GPU, 6144 MiB, драйвер `580.178.04`.
- Python `3.11.11`, torch `2.6.0+cu124`, gliner2 `2.1.0`, Transformers `4.57.1`, tokenizers `0.22.1`.
- FastAPI `0.141.1`, Pydantic `2.13.5`, Uvicorn `0.52.4`.
- Модель `hivetrace/gliner-guard-omni@bda9b81a77421f48bff373d8339adaf225ff8764`, `cuda:0`, `float32`; прежние NER-метки и пороги.
- Отдельный временный контейнер с `--network none`; HTTP-запросы направлялись на loopback внутри контейнера. Веса и датасет подключены только для чтения. Внешних LLM-вызовов нет.
- Образ v4: `sha256:45a8f46a0e7e343257b231065b8b9cc274d38f4e9cecff4ae7f2dd15db7364ee`.
- Образ собран поверх локального образа прошлого замера `sha256:ad41fd73049255432acffffb990c81e78c19709cebd3474c653cab20ebca1477` с заменой кода и профиля. Совпадение `requirements.lock` проверено через `cmp`, `pip check` завершился без ошибок. Контрольные суммы всех Python-файлов приложения и профиля внутри контейнера совпали с текущей рабочей копией.
- Новый контейнер после прогона удалён; ранее запущенный сервис v1 не пересоздавался.

Метрики рассчитаны тем же кодом, что и [результаты v3](result_v3.md): micro F1, сопоставление один к одному, обязательное совпадение типа. В основных таблицах удаляются полностью вложенные предсказания одного типа. Все 13 эталонных классов учитываются, включая неподдерживаемые.

Правила v4 разработаны после просмотра ошибок этого бенчмарка. Показатели ниже показывают эффект исправлений на уже просмотренных данных; для независимой оценки потребуется другая выборка.

## Изменения правил

- Адрес: город с `г.` и без него, регион, необязательные запятые и `д.`, сокращение `пр.`, тип улицы после названия, корпус, строение, квартира, офис, подъезд и этаж.
- Улица без обозначения типа принимается с городом и дополнительными адресными компонентами либо в явном адресном поле/указании доставки. Слова перед адресом, ФИО и соседний телефон исключаются из спана.
- Паспорт: `паспортные данные`, пояснение между паспортным словом и значением, несколько номеров, паспортный контекст после значения, слитные десятизначные номера. В записи `серия 7518 номер 492137` сохраняется вся связанная запись серии и номера.
- Десятизначное число без паспортного контекста не принимается. Явные соседние поля телефона, ИНН, счёта, заказа и другого документа исключают паспортную классификацию. Контекст не переходит через строки, двойные кавычки и точку с запятой.
- Именованные значения и справочник городов из бенчмарка в правила не добавлялись. Ограничено число слов и компонентов; длинные пробелы обрабатываются без перебора их разбиений.

## Время запросов

Последовательный проход 1810 текстов занял около **26.5 с** после готовности модели. Для HTTP-клиента внутри контейнера медиана — **13.917 мс**, p95 — **19.777 мс**. Медиана модельного этапа — 12.394 мс, regex — 0.098 мс, merge — 0.136 мс. Начальная загрузка и прогрев исключены. Это один последовательный прогон коротких текстов, без проверки конкурентной нагрузки.

## Оставшиеся ошибки

- На `entity` остаются пять пропущенных паспортных сущностей: три значения без явного паспортного контекста и две частичные записи — отдельная серия и формулировка «номер был …».
- Модель по-прежнему может выдавать слова «паспорт», частичные серии и другие неверные сущности. Эти кандидаты не удалялись новыми регулярками по одному лишь наличию другого спана.
- Один ранее точный адрес стал длиннее из-за включения подъезда, который в этой строке не входит в эталонную сущность. В других строках бенчмарка подъезд входит в разметку адреса.
- Новые паспортные правила находят оба номера в примере исправления ошибочно переданных паспортных данных; эталон размечает только один из них. В подсчёте это остаётся дополнительным FP.
- Свободные описания местоположения, сложные адреса и номера документов без достаточного контекста требуют дальнейшей работы.

## Проверки и воспроизведение

Добавлены синтетические регрессионные примеры на полные границы адреса, ФИО/телефон перед адресом, соседние поля с числами, Unicode offsets, HTTP-контракт, длинные строки и восстановление отклонённых модельных кандидатов при replay.

Полный CPU-набор: **390 passed, 3 skipped** (отдельные GPU-тесты). Окружение без необязательных HTTP/Pydantic-зависимостей: **311 passed, 17 skipped**. Ruff check и format проходят. Затем выполнен описанный выше полный HTTP/GPU-прогон PII-Bench; отдельная группа `pytest -m gpu` при этом не запускалась.

В фактическом HTTP-прогоне runner запускался через `docker exec` во временном контейнере:

```bash
docker exec pii-bench-v4-20261121T143737Z \
  python -m backend.detectors.scripts.pii_bench collect \
  --items /bench-data/items.jsonl \
  --url http://127.0.0.1:8000 --expected-profile pii-ru-en-v4 \
  --output - > backend/detectors/acceptance-output/pii-bench-v4-gpu-20261121T143737Z/v4-responses.jsonl
python -m backend.detectors.scripts.pii_bench score \
  --responses backend/detectors/acceptance-output/pii-bench-v4-gpu-20261121T143737Z/v4-responses.jsonl \
  --output backend/detectors/acceptance-output/pii-bench-v4-gpu-20261121T143737Z/v4-metrics.json
```

Контейнер из команды уже удалён; образ, Dockerfile, параметры запуска и контрольные суммы сохранены в артефактах.

Для повторения проверки только regex/merge из сохранённых модельных кандидатов — команда из корня репозитория в окружении с `requirements-cpu.lock`:

```bash
python -m backend.detectors.scripts.replay_regex \
  --responses backend/detectors/acceptance-output/pii-bench-cd6a18a-20261121/v3-responses.jsonl \
  --profile backend/detectors/config/profile.toml \
  --output backend/detectors/acceptance-output/regex-v4-new
```

Для контрольного replay v3 вместо текущего профиля используется сохранённый `backend/detectors/acceptance-output/pii-bench-cd6a18a-20261121/profile-v3.toml`.
